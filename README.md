# ドパガキゲーム（Ver.2）

「あなたが無意識にやっているドパガキ行動を、ゲームに騙されながら暴かれる約60秒の診断ゲーム」。

Ver.1の「ポイントを見ながら確定ボタンを押すだけ」というメインゲームは廃止し、
Ver.2では複数の短いミニイベント（タップ・スワイプ・待つ・選択・連打など操作方法が毎回変わる）を
次々にこなす中で、本人に気付かれないままドパガキ行動を測定し、最後に「ドパガキ度○％」として
暴く構成に作り替えた。

タイトル → 測定（ランダムなミニイベント8つ） → 結果画面 → リトライ までの一連の流れを実装済み。

## 起動方法

```bash
npm install
npm run dev
```

表示されたURL（デフォルト `http://localhost:5173/`）をブラウザ（スマホ幅推奨・DevToolsのデバイスモードでもOK）で開く。

本番ビルドは `npm run build`（`dist/` に出力）、`npm run preview` でビルド後の確認ができる。

## 実装した内容

- タイトル→測定→結果→リトライの一連の画面遷移。ステージ感を出さず「1本の測定ゲーム」に見せる
  （画面上部に「測定中 42%」というシンプルな進行表示のみ）
- 最初は必ず説明SKIPイベント、最後は必ず結果罠イベント、中盤はイベントプール10種類から
  ランダムに6つを選出（同じイベントは重複させず、同じ行動カテゴリーが連続しすぎないよう
  ベストエフォートで並び替える）
- 各イベントは「タップ／スワイプ／待つ／選択／連打」など操作方法をイベントごとに変え、
  内部で0〜100のドパガキスコアを算出（ランダムな加点は一切行わず、同じ行動なら同じ評価になる設計）
- スコアが高いイベントの後には、そのプレイヤーの行動に関連した煽り文を約2.2秒表示（読める長さを確保）
- 結果画面では「ドパガキ度○％」を画面内で圧倒的に一番大きく表示し、タイプ名・犯行記録・
  一言コメントを添える。localStorageで初回スコア／自己最低スコア／プレイ回数を保存し、
  自己最低更新時は演出を表示
- 結果シェア：Web Share API対応端末はネイティブ共有、非対応時はX/LINEへのシェアリンク＋
  テキストコピーボタンにフォールバック（PNG画像生成は今回は見送り、テキスト共有と
  スクリーンショット映えのするカードデザインを優先）

## 採用イベント一覧（12種）

| ID | 名称 | 操作方法 | カテゴリー |
|---|---|---|---|
| skip | 説明SKIP（固定・最初） | タップ | skip |
| loading | 99%ロード | 待つ／タップ | impatience |
| rapidTap | 次へ連打 | 連打 | impulse |
| notification | 偽通知 | タップ | notification |
| stimulusFree | 無刺激移動 | 待つ／タップ | stimulation |
| shortContent | ショート送り | 上スワイプ | stimulation |
| tapSpeed | タップ高速化 | 連打 | impulse |
| unresponsive | 無反応タイム | 何もしない（裏で操作を計測） | impatience |
| instantReward | 即時報酬 vs 待つ | 選択 | impulse |
| speedToggle | 2倍速 | 選択（トグル） | stimulation |
| fakeResult | 偽結果 | タップ | result |
| finalTrap | 最後の結果罠（固定・最後） | タップ／待つ | result |

## ドパガキ度の計算方法

1. 各イベントは測定した行動（反応までの秒数、タップ回数など）から`src/config/gameConfigV2.ts`の
   帯（`bands`/`tapBands`）に従って0〜100の「イベントスコア」を算出する。ランダム要素は無いため、
   同じ操作をすれば必ず同じスコアになる。
2. 全イベントのスコアの単純平均を取り、四捨五入した値を「ドパガキ度（0〜100%）」とする
   （`src/engine/resultEngineV2.ts` の `computeDopagakiResult`）。

## タイプ判定方法

- ドパガキ度が0〜15%：「ほぼ仙人」（固定）
- 16〜34%：「意外と理性ある型」（固定）
- 35%以上：そのプレイで登場したイベントを行動カテゴリー（skip / impatience / stimulation /
  notification / impulse / result）ごとに平均し、最もスコアが高かったカテゴリーに対応する
  タイプ名を採用（例：stimulationが最高なら「刺激中毒型ドパガキ」）

犯行記録は、スコアが`crimeThreshold`（初期値55）以上だったイベントの生成文の中から、
スコアが高い順に最大3件を結果画面に表示する。

## 今後簡単に調整できるファイル

- `src/config/gameConfigV2.ts`：イベントの時間・出現タイミング・採点の帯（何秒/何回で何点か）、
  煽り発生の閾値と表示時間、犯行記録の閾値、中盤で選ぶイベント数など、数値はすべてここに集約
- `src/config/messagesV2.ts`：タイトル文言、イベント別の煽り文プール、犯行記録の文章テンプレート、
  タイプ名、結果コメント（高/中/低）、シェア文面
- `src/engine/eventPool.ts`：イベントの出現有無・出現順序ロジック（プールから何を採用するか、
  カテゴリーの連続回避ロジック）
- `src/engine/resultEngineV2.ts`：ドパガキ度の統合方法・タイプ判定ロジック（現在は単純平均。
  カテゴリーごとの重み付けなど、後から拡張しやすい構造にしてある）
- `src/events/*.tsx`：個々のイベントの見た目や挙動そのものを変えたい場合

## 動作確認結果

- `npx tsc --noEmit` / `npm run build` / `npm run lint` すべて問題なし
- Playwright（Chromiumヘッドレス、390×844のスマホ相当ビューポート）で以下を確認
  - 「積極的に反応・連打・SKIPし続けるプレイヤー」を自動操作したプレイ：結果88〜91%、
    所要約30秒、コンソールエラー0件
  - 「ほぼ何もしない・待つを選ぶプレイヤー」を自動操作したプレイ：結果11%、所要約37秒、
    コンソールエラー0件
  - 上記6回の追加プレイでも76〜90%の範囲で自然にばらつき、コンソールエラー0件。
    犯行記録が実際の操作内容（タップ回数・反応秒数）と一致することを確認
  - 次へ連打イベントの「有効化前のタップも計測される」仕様、ショート送りイベントの
    上スワイプ判定（iPhone想定のポインタージェスチャー）が正しく動作することを個別に確認
  - リトライ後、新しいランダムなイベント構成で再度プレイできることを確認
  - localStorageの初回スコア／自己最低スコア／プレイ回数が正しく保存されることを確認
- いずれのプレイでもドパガキ度は0〜100%の範囲を超えず、途中で操作不能になる詰みは発生しなかった
