# ドパガキゲーム（Ver.3）

表向きの目的は「60秒でできるだけ高いGAME SCOREを取る」こと。
その裏で、プレイヤーが高スコアを狙う過程で無意識に取る行動
（説明SKIP、2倍速の任意使用、連打、即時報酬への飛びつき、通知への反応、
結果の先取りなど）を記録し、GAME SCOREとは完全に切り離した
「ドパガキ度」として最後に暴く構成。

タイトル → プレイ（ランダムなミニイベント7〜8個、約55〜65秒） → 結果画面 → リトライ。

## 起動方法

```bash
npm install
npm run dev
```

表示されたURL（デフォルト `http://localhost:5173/`）をブラウザ（スマホ幅推奨・DevToolsのデバイスモードでもOK）で開く。

本番ビルドは `npm run build`（`dist/` に出力）、`npm run preview` でビルド後の確認ができる。

## Ver.3の核となる設計

Ver.2の反省（「なぜ2倍速にするのか」等、行動の動機がなかった）を踏まえ、
すべてのイベントに「目的・成功条件・失敗条件・GAME SCORE報酬」を持たせた。
そのうえで、**GAME SCORE（表のスコア）とドパガキ診断（裏の測定）を完全に分離**しており、
ドパガキ的な行動（2倍速を使う、通知に反応する等）をしても、それ自体がGAME SCORE上
不利になるとは限らない設計にしてある（実測でも「高GAME SCORE×高ドパガキ度」の
組み合わせが実際に発生することを確認済み）。

## 実装イベント（11種）

| ID | 名称 | 目的・成功条件 | 診断カテゴリー |
|---|---|---|---|
| videoMemory (A) | 動画記憶ゲーム | 図形の出現数を答えて正解＋1000。2倍速は時間短縮に使える | speed |
| skipQuiz (B) | 説明SKIPクイズ | 説明を読んで（またはSKIPして）クイズに正解＋1000 | skip |
| comboBoost (C) | 連打ブースト | ゲージ100％到達で＋700。連打すると早く貯まる | impulse |
| instantReward (D) | 即時報酬 | 今すぐ＋300 か、3秒待って＋1000 か | impulse |
| notificationReflex (E) | 通知妨害 | 青くなった瞬間タップで＋500。BONUS通知は30％で＋500だが反射を妨げるリスクあり | notification |
| sortRush (F) | 高速仕分け | 食べ物→右／それ以外→左に仕分け、正解＋200・誤答−50 | stimulation |
| holdRelease (G) | 長押し耐久 | 最大5秒保持で＋1000。1秒ごとに離した時点の報酬が確定 | patience |
| adCountdown (H) | 広告風カウントダウン | 5秒待てば＋900。SKIPすると0だが時間節約 | skip |
| treasureBox (I) | 宝箱 | 3箱から当たりを選択＋1200。3秒待つとハズレが1つ消える | impulse |
| peekResult (J・終盤限定/低確率) | 途中診断チラ見 | GAME SCOREは変動しない、診断専用の寄り道イベント | result |
| gambleChoice (K) | 安全策 vs 一発逆転 | 確実に＋500 か、50％で＋1500/0 か。診断への影響は弱め | impulse（重み0.3） |

EVENT L（制限時間クイズ）は仕様書内で「優先度低め」と明記されていたため、
他の11イベントで十分な種類とテンポが確保できると判断し、実装を見送った。

## GAME SCOREの仕組み

各イベントの`onComplete`が返す`scoreDelta`（正誤・報酬選択・ミス数などに応じて増減、
`sortRush`のように誤答で減点されるケースもある）を単純に合算するだけ。ドパガキ診断の
スコアとは完全に別の値として管理しており（`src/screens/PlayScreen.tsx`）、
診断ロジック側から一切参照しない。

## ドパガキ度の計算方法

各イベントは「診断対象になる行動をしたときだけ」`diagnostic.score`（0〜100、
ランダム要素なし＝同じ行動なら毎回同じ値）を返す。プレイ終了時、実際に発生した
診断結果の**重み付き平均**（既定重み1。`gambleChoice`だけ重み0.3で影響を弱めている）
を四捨五入した値が最終的なドパガキ度（0〜100％）。GAME SCOREは一切加味しない
（`src/engine/resultEngineV3.ts`）。

## タイプ判定方法

- 0〜15%：「ほぼ仙人」（固定）
- 16〜30%：「意外と理性ある型」（固定）
- 31%以上：そのプレイで登場した診断カテゴリー（skip / speed / impulse / stimulation /
  notification / patience / result）ごとの平均スコアを比較し、最も高かったカテゴリーに
  対応するタイプ名を採用（例：speedが最高なら「効率厨型ドパガキ」）

## 犯行記録の仕組み

`diagnostic.score`が`crimeThreshold`（初期値55）以上だったイベントの生成文の中から、
スコアが高い順に最大3件を結果画面に表示する。単純なゲームの上手さ（反応速度・正答率）
だけでは診断・犯行記録の対象にならないよう、各イベントの診断ロジックは
「任意の高速化・不要な連打・即時報酬への飛びつき」など"自ら刺激/効率を取りに行った行動"
だけを評価するようにしてある。

## ランダム化部分

- `src/engine/eventPoolV3.ts`：A〜I・Kの10候補から毎回7〜8個をランダム選出し、
  同じ行動カテゴリーが連続しすぎないようベストエフォートで並び替え。EVENT J（途中診断
  チラ見）は30％の確率で終盤の追加イベントとして差し込まれる
- 各イベント内部の問題文・数値・報酬・当たり外れなどもプレイごとにランダム化
  （例：動画記憶の図形列、説明SKIPクイズの問題、宝箱の当たり位置、通知の当落など）

## 動作確認結果

- `npx tsc --noEmit` / `npm run build` / `npm run lint` すべて成功
  （lintの警告はVer.1/Ver.2から継続する軽微なもののみで、ビルドを妨げない）
- Playwright（Chromiumヘッドレス、390×844のスマホ相当ビューポート）で以下を確認
  - 「積極的にSKIP・2倍速・即時回収・通知反応をするプレイヤー」を自動操作：
    5回連続プレイで ドパガキ度67〜76%・GAME SCORE 2,500〜4,400、コンソールエラー0件
    （高GAME SCORE×高ドパガキ度が両立するケースも確認）
  - 「待てるものはすべて待つ・SKIPしない・長押しを最後まで保持するプレイヤー」を
    自動操作：ドパガキ度15%（「ほぼ仙人」）・GAME SCORE 4,800、コンソールエラー0件
  - 実装中に発見・修正したバグ：説明SKIPクイズでSKIPを一度も押さない場合に
    クイズへ進めなくなる詰みがあったため、読了後の自動進行タイマーを追加。
    長押し耐久イベントでボタンを押す前にアニメーションループが停止し、
    後から押しても表示が更新されない不具合を修正
  - 犯行記録が実際の操作内容（2倍速までの秒数・連打回数・SKIPまでの秒数など）と
    一致することを確認
  - リトライ後に新しいランダムなイベント構成で再プレイできることを確認
  - localStorage（`gameHighScore` / `lowestDopagaki` / `firstDopagaki` / `playCount`）の
    保存が正しく行われることを確認
  - いずれのプレイでもドパガキ度は0〜100%の範囲を超えず、途中で操作不能になる詰みは
    発生しなかった（上記の2件を除く。いずれも修正済み）

## 今後簡単に調整できるファイル

- `src/config/gameConfigV3.ts`：制限時間、イベントごとの報酬額・時間・採点の帯、
  イベント数・EVENT J出現確率・犯行記録の閾値など、数値はすべてここに集約
- `src/config/messagesV3.ts`：タイトル文言、イベント開始時の指示文、タイプ名、
  結果コメント、リトライ文言、シェア文面
- `src/engine/eventPoolV3.ts`：イベントの出現有無・出現順序ロジック
- `src/engine/resultEngineV3.ts`：ドパガキ度の統合方法・タイプ判定ロジック
- `src/events/*.tsx`：個々のイベントの見た目・報酬・診断ロジックそのもの
