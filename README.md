# ドパガキゲーム（Ver.4.1）

Ver.3系の「イベントを1つずつこなす診断ゲーム」を廃止し、**「60秒で刺激をさばき続ける高速リズムゲーム」**
そのものに作り替えた。診断色を消し、ゲーム自体がドパガキ的な体験になることを最優先している。

Ver.4.1では**ゲーム構造は変更せず**、実機プレイで見つかったスコアバランス・お題の不可能状態・
テンポ・タイプ判定の甘さを修正した（詳細は「Ver.4.1でのバランス調整」を参照）。

タイトル → プレイ（固定60秒・お題が絶え間なく切り替わる） → 結果画面 → リトライ。

## 起動方法

```bash
npm install
npm run dev
```

表示されたURL（デフォルト `http://localhost:5173/`）をブラウザ（スマホ幅推奨・DevToolsのデバイスモードでもOK）で開く。

本番ビルドは `npm run build`（`dist/` に出力）、`npm run preview` でビルド後の確認ができる。

## Ver.4の核となる設計

- 主役の数値は**ドパガキ度（0〜100%、隠し条件を満たすと120%まで）のみ**。旧GAME SCOREは廃止した
- 中央に1問ずつ高速でお題を出し、正誤・反応速度に応じてPERFECT/GREAT/GOOD/MISSを判定してドパガキ度が
  滑らかに増減する。問題間の遷移は約190msと短く、「一つの高速ラッシュゲーム」に感じるようにした
- 60秒を6段階（ウォームアップ→ランプアップ→フェイクゾーン→DOPA BOOST→刺激過多ゾーン→
  FINAL DOPA RUSH）に分け、出題速度・出題プール・演出レベルが段階的に上がる
- COMBOは連続正解で増加、MISSで0にリセット。COMBOに応じて加点が増えるほか、画面の発光／ネオン／
  パーティクル／ゴールド演出が豪華になる（お題の視認性は常に最優先）
- 残り10秒でFINAL DOPA RUSH（赤い警告ランプが点滅、残り時間に応じて点滅速度上昇）、残り3秒で
  大きく3・2・1を表示するが、お題自体は止まらず出続ける
- 100%到達時は一瞬静止＋金色の爆発演出。裏の隠し条件（高精度＋高反応＋その他3条件中2つ）を満たした
  プレイヤーだけ、100%を超えてDOPA OVERDRIVE（最大120%）に突入できる。条件はゲーム内で一切説明しない

## お題13種

A.色選択／B.仲間外れ／C.最大数字／D.最小数字／E.違うもの／F.同じもの／G.多い方／H.大きい方／
I.簡単な計算／J.スワイプ／K.連打／L.長押し／M.押すな、を実装。難易度フェーズごとに出題候補プールを
変え、`src/questions/` に1問1ファイルで実装しているため、新しい問題タイプを追加してもGame本体を
編集せずに済む構造にしてある（`src/questions/index.ts` に登録するだけ）。

## 判定・スコアの仕組み（Ver.4.1で刷新）

- 判定は固定ミリ秒ではなく `反応時間 / その問題のtargetTimeMs` の比率で決める
  （PERFECT: 35%以内 / GREAT: 60%以内 / GOOD: 100%以内 / それ以外はMISS）。長押し・押すな等
  「速さ」で測れない問題は成功/失敗の二値でPERFECT・MISSを直接割り当てる
- ドパガキ度は「1問ごとの質スコア（PERFECT=100/GREAT=90/GOOD=85、MISSは0点）＋COMBOボーナス」の
  **平均値**（`qualitySumRef ÷ answeredCountRef`）。Ver.4は累積加算方式だったため出題数（＝速さ×時間）
  が多いほど正答率に関わらずスコアが積み上がってしまっていたが、平均方式にしたことで出題数を
  稼いでもドパガキ度は上がらず、正答率が素直に反映されるようになった
- 正答率に応じた上限（`ACCURACY_CAPS`、例：70%未満→75%、90〜94%→99%、95%以上→100%到達可）を
  平均値にかけ合わせ、たとえ判定・COMBOで高い値が出ても正答率が低ければ100%に到達できないようにした
- すべて `src/config/scoreConfigV4.ts` に集約
- OVERDRIVEの隠し条件（高速反応・高精度・高COMBO・せっかち行動・待てなさの5カテゴリー中、
  高精度＋高反応＋残り3条件中2つ）は `src/config/overdriveConfig.ts` に集約。Ver.4.1では
  平均ベースのスコアで100%到達自体が簡単になった分、`accuracyThreshold`（0.85→0.92）と
  `reactionRatioThreshold`（0.45→0.4）を引き上げ、OVERDRIVEがより高精度プレイ限定になるよう調整した
- 各お題タイプには「速度倍率だけでは表現できない物理的な最低制限時間」を返す
  `computeMinTargetTimeMs` を実装し（`src/config/timingConfig.ts` に集約）、後半の高速化で
  HOLDや連打の必要時間より制限時間が短くなり「絶対にクリアできない」状態になるバグを解消した
- PERFECT/GREAT/GOODなどの判定表示は、次のお題の出現を待たせずオーバーレイ表示するようにした
  （`src/screens/PlayScreen.tsx`）。100%到達／OVERDRIVE突入の瞬間だけは演出のため意図的に一瞬静止する

## 結果画面

最大表示は常に「ドパガキ度」。その下にタイプ名、さらに小さく最大COMBO／最速反応／正答率を表示し、
GAME SCOREは表示しない。99%終了時は「あと1％でした。」のような悔しさを煽るコメントを出す。
タイプ名は通常時（脳直高速処理型／連打中毒型／高速フリック型／待てない型／刺激処理マシーン／
完全体ドパガキ／ドパガキ見習い／バランス型）とOVERDRIVE時（限界突破ドパガキ〜ドパガキ最終形態）で
分けて `src/config/resultTypesV4.ts` に定義。犯行記録はゲームログから自動生成し、最もネタになる2件を表示する。

**Ver.4.1でのタイプ判定の厳格化**：Ver.4では「反応時間/制限時間の比率が0.55以下」というだけで
脳直高速処理型が付与され、最速反応0.73秒程度の緩いプレイでも該当してしまっていた。Ver.4.1では
`src/config/resultTypesV4.ts` の `TYPE_THRESHOLDS` に、最低サンプル数・比率・絶対反応時間(ms)・
正答率を組み合わせた閾値を定義し、`src/engine/resultEngineV4.ts` の `determineType()` を
「どの条件も明確に満たさない場合は汎用の『バランス型ドパガキ』にフォールバックする」方式に変更した。
「押すな」を実際に複数回押してしまった場合の「待てない型」判定は好評だったため、最優先の判定として維持している。

## 動作確認結果

### Ver.4（初期実装時）

- `npx tsc --noEmit` / `npm run build` / `npm run lint` すべて成功
  （lintの警告は各お題ファイルの構造に起因する軽微なFast Refresh警告のみで、ビルドを妨げない）
- Playwright（Chromiumヘッドレス、390×844のスマホ相当ビューポート）で以下を確認
  - 素朴なプレイ（適当にボタンを押すだけ）で60秒間クラッシュせずプレイ完走、コンソールエラー0件
  - 色・数字・計算・同じもの／違うものを正しく判定して答える強化ボットで、ドパガキ度が
    0%→100%まで滑らかに上昇し、100%到達時の「静止→金色演出→完全体ドパガキ」が正しく発火することを確認
  - FINAL DOPA RUSH演出が残り10秒（t=51.8〜52.0s）で発火、赤いランプ点滅、残り3秒台で大きな
    「3」がお題を止めずに重なって表示されることをスクリーンショットで確認
  - MISS時の画面シェイク・赤フラッシュ・COMBO BREAK表示が動作することを確認
  - リトライで60%まで達成した場合など、結果に応じたリトライ文言（「その先へ」等）が正しく出ることを確認
  - 実装中に発見・修正したバグ：`statsRef.current.maxCombo` が最終結果に反映されていなかった問題を修正

### Ver.4.1（今回のバランス調整）

- `npx tsc --noEmit` / `npm run build` / `npm run lint` すべて成功（新規追加分含めエラーなし）
- **スコアシミュレーション（Node.js、実際の`scoreConfigV4.ts`の数式を再現）**：
  正答率60/70/80/90/95/98%それぞれについて、判定分布を正答率相応に仮定した20000試行の平均値は
  56.8% / 67.4% / 78.3% / 89.2% / 94.7% / 98.1% となり、指示された目標バンド
  （60%→50-65%、70%→60-75%、80%→70-85%、90%→85-95%、95%以上＋高反応＋高COMBO→95-100%）に
  収まることを確認した
- **Playwright実プレイテスト**（Chromiumヘッドレス、実際にゲームをプレイするボットで60秒×6回）：
  - 正答率60/70/80/90%を狙うボットで実際にプレイした結果、ドパガキ度はそれぞれ
    60% / 70% / 83% / 94% となり目標バンド内。70/80/90%のいずれも100%には到達しなかった
    （正答率キャップにより上限85/94/99%で頭打ち）ことを確認
  - 正答率98%＋即座に反応する強ボットでドパガキ度100%に到達することを確認（95%以上＋高反応＋高COMBOでの
    100%到達可能性を確認）
  - 正答率30%の低精度ボットではドパガキ度32%止まりで、OVERDRIVEには一切到達しないことを確認
  - **常に成功を狙うボット（60秒間で1035問・ノーミス）でHOLD/連打/押すな/スワイプの成功率がいずれも
    100%（10/10, 58/58, 26/26, 59/59）**となり、最終盤の高速フェーズを含め物理的に詰む出題が
    発生しないことを確認（`computeMinTargetTimeMs`による下限保証が機能している）
  - 上記いずれの実行でもコンソールエラーは0件
  - 判定オーバーレイ化により、ボットが即応答した場合60秒間で700〜1000問超のテンポが出ることを確認
    （旧仕様の待機ギャップが解消されたことの間接的な裏付け）
- iPhone Safari実機での最終確認は未実施（後述の「重点確認ポイント」を参照）

## 今後簡単に調整できるファイル

- `src/config/difficultyConfig.ts`：6段階の時間帯・出題速度・出題プール
- `src/config/scoreConfigV4.ts`：判定ごとの質スコア・COMBOボーナス・正答率別の到達上限（`ACCURACY_CAPS`）
- `src/config/timingConfig.ts`：HOLD／連打／スワイプ／計算問題の物理的な最低制限時間
- `src/config/overdriveConfig.ts`：DOPA OVERDRIVEの隠し発動条件の閾値
- `src/config/visualConfig.ts`：演出レベル（発光／ネオン／パーティクル／ゴールド／ギラギラ）の定義
- `src/config/resultTypesV4.ts`：タイプ名（通常／OVERDRIVE称号）とタイプ判定の閾値（`TYPE_THRESHOLDS`）
- `src/config/messagesV4.ts`：タイトル文言・リトライ文言・結果コメント・シェア文面
- `src/questions/*.tsx`：お題の追加・見た目・難易度調整（1問1ファイル）
- `src/utils/sound.ts`：効果音（Web Audio APIの簡易SE。音源ファイルへの差し替えも容易）

## スマホ実機で重点的に確認してほしいポイント

- iPhone Safariで長押し（HOLD・「押すな」）時にテキスト選択やコールアウトメニューが出ないか
- スワイプ問題でブラウザの戻る/進む操作や画面スクロールが誤発火しないか
- 連打・ダブルタップでズームが暴発しないか
- FINAL DOPA RUSHやパーティクル演出が重く感じないか（低スペック端末での体感）
- 実際に上手くプレイした際、DOPA OVERDRIVEが自然に発動する体感になっているか
  （閾値は`overdriveConfig.ts`でいつでも調整可能）。Playwrightボットでの検証では、
  「正答率・反応速度は高いが押すな／先走りタップが一切ない完璧すぎるプレイ」だとOVERDRIVEの
  追加条件（高COMBO／せっかちタップ／押すな失敗のうち2つ以上）を満たさず発動しなかった。
  実機で人間らしいプレイをした際に自然に発動するか、体感を重点的に確認してほしい
- 判定オーバーレイ（PERFECT/GREAT/GOOD/MISS）が次のお題の上に一瞬重なって表示され、
  お題の切り替えテンポを妨げていないか（旧仕様は表示中お題が止まって見えていた）
- HOLD・連打・「押すな」がFINAL DOPA RUSH中（残り10秒以降）でも実際に無理なくクリアできるか
